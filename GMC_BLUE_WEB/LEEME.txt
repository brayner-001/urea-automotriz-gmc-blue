GMC BLUE - SITIO WEB CON DISEÑO MEJORADO
========================================

ARCHIVOS PRINCIPALES
- index.html: estructura de la página.
- styles.css: diseño, animaciones y adaptación a móviles.
- script.js: menú, cotizador, WhatsApp, correo y animaciones de entrada.
- assets/: fotografías y logotipo de GMC BLUE.

- assets/video-posters/: portadas extraídas de los videos.

MEJORAS REALIZADAS

1. Descomprime GMC_BLUE_WEB_DISENO_MEJORADO.zip.
2. Abre la carpeta en Visual Studio Code.
3. Abre index.html con Live Server.
4. No separes index.html, styles.css, script.js ni la carpeta assets.

------------------------------------------------------------
NUEVA INTEGRACION: CUENTAS DE CLIENTES CON SUPABASE
------------------------------------------------------------

Se añadió un acceso "Mi cuenta" en el encabezado, con:
- Registro con nombre, correo y contraseña.
- Inicio y cierre de sesión.
- Persistencia de sesión mediante Supabase Auth.
- Consulta del rol propio (cliente/administrador) respetando RLS.
- Mensajes de confirmación y error en español.

Archivo nuevo: auth.js
La librería @supabase/supabase-js se carga desde jsDelivr en index.html.

Configuración necesaria en Supabase antes de probar el registro:
1. En Authentication > URL Configuration, configura Site URL con el dominio
   publicado de GMC BLUE en Cloudflare Pages.
2. Añade también el dominio de pruebas local (por ejemplo, http://localhost:5500)
   a Redirect URLs si vas a probar con un servidor local.
3. Revisa si está activada la confirmación de correo. Si está activada, el cliente
   deberá confirmar su correo antes de iniciar sesión.
4. Mantén habilitada la seguridad RLS en las tablas públicas. La publishable key
   está diseñada para el navegador; nunca coloques una secret key o service_role
   en archivos frontend.

Nota: el formulario inicial guarda el nombre en los metadatos de Supabase Auth.
El trigger existente handle_new_user() crea el perfil y asigna el rol customer.
El campo teléfono no se solicita todavía; lo integraremos después de decidir
cómo guardar y validar ese dato en profiles.

AVANCE LOCAL - FASE 1: PREPARACION DEL CATALOGO SUPABASE
--------------------------------------------------------

Se añadió catalog.js y se conectó después de auth.js.
- Reutiliza el cliente Supabase ya inicializado por auth.js.
- Ejecuta únicamente SELECT sobre public.products, filtrando active = true.
- Lee id, name, sku, description, price, image_url y active.
- Si la consulta funciona y devuelve productos válidos, actualiza las tarjetas
  del catálogo y las opciones del cotizador.
- Si Data API no expone la tabla, falla la conexión o no hay productos activos,
  conserva las cuatro tarjetas locales y sus precios de prototipo (S/ 65, S/ 58,
  S/ 529 y el IBC a cotizar).
- Los textos del catálogo dinámico se insertan mediante APIs DOM/textContent,
  no mediante HTML interpolado.
- El clic de agregar al carrito usa delegación de eventos para seguir funcionando
  después de actualizar las tarjetas.

IMPORTANTE - DEPENDENCIA EXTERNA PENDIENTE:
La última revisión documentada de Supabase indicaba 0 de 5 tablas expuestas en
Data API. Por ello, este ZIP prepara la integración y el fallback seguro, pero
no puede completar una lectura real de products hasta que exista una vía de
acceso autorizada. No se modificaron tablas, datos, grants, exposición, RLS,
funciones, triggers, usuarios ni configuración de Supabase.

Para completar la conexión real se debe decidir y autorizar una de estas vías:
1. Exponer únicamente public.products con grants mínimos revisados y RLS
   conservada; o
2. Crear una función backend/Edge Function de solo lectura que publique solo
   los campos de productos activos, con secretos almacenados en el entorno
   backend (nunca en JavaScript del navegador).

No pulsar Save en Data API ni cambiar grants a ciegas: Supabase había advertido
que guardar desde esa pantalla podía revocar grants personalizados.

BACKEND DE CATÁLOGO GMC BLUE (PREPARACIÓN LOCAL - FASE 1)
------------------------------------------------------------

Se añadió una integración del catálogo con una Edge Function:
- catalog.js consulta GET /functions/v1/catalog.
- Si la función no está desplegada o falla, se conserva el catálogo de prototipo.
- La función solo devuelve productos activos y un conjunto limitado de columnas.
- La función utiliza una conexión de base de datos de solo lectura configurada como secreto del backend.
- No se exponen tablas nuevas mediante Data API desde el navegador.

Archivos nuevos:
- supabase/functions/catalog/index.ts: endpoint de lectura del catálogo.
- supabase/config.toml: configuración pública de invocación de la función.
- supabase/auditoria_catalogo.sql: consultas SQL de solo lectura para revisar grants, RLS, columnas y roles.
- supabase/README.md: arquitectura y pasos previos al despliegue.

IMPORTANTE:
La función está preparada localmente, pero NO está desplegada ni conectada a producción.
Antes de desplegarla se debe ejecutar y revisar supabase/auditoria_catalogo.sql. Después se debe crear y aprobar un rol de base de datos dedicado con SELECT únicamente sobre las columnas públicas requeridas. La contraseña/cadena de conexión debe configurarse como secreto GMC_CATALOG_DATABASE_URL en Supabase, nunca en archivos frontend ni en GitHub.
No se han modificado tablas, datos, roles, grants, políticas RLS ni configuración del proyecto Supabase.
